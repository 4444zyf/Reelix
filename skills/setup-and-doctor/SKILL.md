# Setup and doctor

`reelix doctor` checks everything; run it first when anything looks wrong and read every FAIL and WARN (WARN: something works with limits, such as a missing ffprobe or 7-Zip). Each line names the check and its details, and `fix:` gives a command when there is one. `--` lines were skipped (a prerequisite is missing), not tested (Jackett's indexers before `reelix jackett indexers --test`, the hard link while the download folder holds no file) or are optional and not used. One cause found by two checks is one line ("also …"). The operation `plugin.check` with `{"plugin":"<id>"}` runs one plugin's checks alone (Settings' "Test connection"; call it through the reelix tool, since `reelix plugin check` in the shell is the checker for plugin authors); `reelix media folder_checks` gives each folder's four results: exists, writable, hard link from the downloads, seen by the media server. The owner sees the same results in Settings → Doctor, in their language, each with a button to the field to fix: point them there by its name rather than giving a config key.

**First-run setup** (one step at a time, confirm as you go):
1. Look under /media (`ls`, `find /media -maxdepth 3 -type d`) and compare with the pre-flight report if the owner has one. Identify the download folder (`reelix config set downloads …`) and the library folders under the same mount: existing folders Jellyfin already scans, or `library/{Movies,Shows,Anime}`. Each media type is a list of folders: the owner's confirmation (below) with path `library` and value `{"movies":[{"path":"/media/library/Movies"}],"shows":[…],"anime":[…]}`. When Jellyfin has several libraries for one type (say Chinese-language and international films), list each folder and follow the skill library-folders.
2. Ask for qBittorrent, Jackett, (optional) Jellyfin addresses. qBittorrent and Jackett are plugins: use the owner's confirmation (below) with path `plugins.qbittorrent` and value `{"url":"http://…","username":"admin"}`, and with path `plugins.jackett.servers` and value `[{"url":"http://…"}]` (a list: each server becomes its own indexer provider). Jellyfin is a plugin too: path `plugins.jellyfin`, value `{"url":"http://…"}` (optionally `public_url`, the address phones open, and `watch_users`, whose history shapes suggestions). Take passwords and API keys ONLY through the ask tool's secret field (kind=secret, key=plugins.qbittorrent.password / plugins.jackett.api_key / plugins.jellyfin.api_key / tmdb.api_key). Test each with `reelix doctor --quick`. After qBittorrent refuses a login (or bans the address), Reelix sends no more logins until its username or password is changed or the Doctor check runs, because qBittorrent bans an address after a few failed logins; say so when downloads stop for this reason.
3. The downloader: Reelix downloads through one downloader plugin, the owner's choice (`downloader`, default `qbittorrent`; `reelix download downloaders` lists what is running). Only the owner changes it, in Settings → Services → Downloader. Its path map: `reelix qbittorrent prefs` shows qBittorrent's save path (its view). Find the same folder under /media (match folder names and torrent names from `reelix qbittorrent torrents`), then `reelix config set path_maps.downloaders.qbittorrent '[{"theirs":"/downloads","ours":"/media/torrents"}]'` (the key is the downloader's id). The media server is chosen the same way (`media_server`, default `jellyfin`, optional; `reelix library media_servers`), and its view of the library is `path_maps.media_servers.jellyfin`. The Doctor checks "downloader" and "media server" say whether the maps are right.
4. Hard-link test from inside: `reelix doctor` does it with a real file the downloader wrote. EXDEV = different mounts/shared folders (fix the layout, not Reelix); EPERM = Reelix is not running as the downloader's user.
5. Indexers: `reelix jackett indexers --test` (a plugin's operation: it needs the running server).
6. Proxy if TMDB or the model provider is unreachable: the owner's confirmation (below) with path `proxy` and value `{"default":"http://host:7890","use_for":["tmdb","subhd","telegram","models","browser"]}`.
7. Ask a few questions (resolution, size limits, HDR, subtitles, audio language, anime groups) and write `/data/notes/preferences.md` in plain language.
8. Telegram: the owner creates a bot with @BotFather and gives the token through the secret field (plugins.telegram.bot_token); then the owner presses "Get a linking code" on the telegram plugin's page (Settings → Services → Telegram) and sends that one-time code to the bot; linking is theirs, and you cannot run it. Whether answers in Telegram may approve destructive actions is the owner's own switch in Settings → Notifications.
9. Summarise the settings (`reelix config show`) for the owner to correct.

**The owner's confirmation.** Only the owner decides where Reelix connects and how far you may go: everything under `plugins`, `proxy`, `web` and `limits` (your own daily spending, shell time limits and the like), the library folders and their rules (`library`), the active `downloader`, `media_server` and `translator`, a plugin's model budget (`plugin.model`, owner only), and the address of a service whose secret is already stored (`magpie.url`, `tmdb.base_url`). `reelix config set` from the shell is refused for these. Call the `reelix` tool with command=config.set and input `{"path":…,"value":…}`: Reelix shows the owner the exact change and asks; on a yes the change is made. In a background job the question goes to the Inbox and the job parks; call it again with the same input when resumed with the yes. The owner can also make the change in Settings.

**Changing other services:** `reelix qbittorrent prefs` / `reelix qbittorrent set_prefs --prefs '{…}'` (operations of the qbittorrent plugin: they need the running server); Jackett indexers can be listed and tested by API, but adding or repairing one is done in Jackett's web page with the browser tools.

**A model that fails:** `reelix model test` (or `reelix model test background`, any role) asks the role's models one short question and reports which one answered, how long it took, and why each failed: signed out (the owner signs in again in Settings → Models), timed out (retry), rate limited or budget reached (wait, until the time shown), a capability it lacks (the owner chooses a model that can). Reelix only ever uses the models in the role's list, so a role with one model has nothing to fall back on: suggest a second one to the owner. Signing in to a provider is the owner's: `docker compose exec -u <PUID>:<PGID> reelix pi`, then `/login`.

Record quirks you discover (slow indexer, odd paths) in `/data/notes/library.md`.
