# Languages

Reelix speaks **English, 简体中文, Français and Русский**.

## What follows the owner's language

| Surface | How |
| --- | --- |
| **Web UI** | i18next: `packages/web/src/locales/<lang>/<namespace>.json`. Dates, relative times, numbers and byte units use `Intl` in the UI language. |
| **Server messages** (chat channel replies, Inbox notices, the morning summary, adopt plans, confirm buttons) | `packages/core/locales/<lang>.json` through `tr(app, key, vars)` (`packages/core/src/i18n.ts`). |
| **Plugin messages** | `plugins/<id>/locales/<lang>.json` through `ctx.t(key, vars)`; English is the fallback. Built-in plugins have all four languages. |
| **Film and show metadata** (titles, overviews, posters from TMDB) | Fetched in the owner's language (`en-US`, `zh-CN`, `fr-FR`, `ru-RU`). When the language changes, a background job re-reads every title (`title.refresh_metadata`). Library folder names never change, and Chinese subtitle sites are still searched with the Chinese title. |
| **The agent** | The system prompt tells it to answer in whatever language the owner writes in, and to use the owner's language for everything it starts itself (notices, questions, job summaries, Telegram). |

The owner's language is the config setting `language` (`en`, `zh`, `fr` or `ru`). Changing it in **Settings → Appearance**, or in the owner menu, saves it on the server and switches the browser. Until it is set, the browser's own language is used (`navigator.languages`, falling back to English).

`GET /api/session` returns `language` without sign-in, so the sign-in page is shown in the right language.

There is one language setting; the old `tmdb.language` is migrated into `language` (`zh-CN` → `zh`) and removed.

Some things stay as they are:
- **Data:** release names, file paths, commands, and messages already written (chat history, earlier inbox items).

## Web UI files

| Namespace | Covers |
| --- | --- |
| `common` | actions, states, units, durations, shared phrases |
| `nav` | sidebar, bottom bar, sign-in |
| `appearance` | language and theme pickers |
| `chat` | conversation, composer, cards |
| `media` | downloads, releases, subtitles, follows, search |
| `library` | library wall, title page, adopt |
| `settings` | settings screen |
| `activity` | activity, inbox, browser |

Conventions:
- In a component, `const { t } = useTranslation("chat")`. To reach another namespace, use `useTranslation(["chat", "common"])` and then `t("common:actions.save")`. Outside components, use `i18n.t("chat:…")`.
- Keys are type-checked against English (`src/i18next.d.ts`): a missing or misspelled key is a compile error.
- Use one key with `{{placeholders}}` per sentence. Never assemble a sentence from translated fragments.
- Plurals use `count`. English needs `_one`/`_other`, Chinese `_other`, French `_one`/`_many`/`_other`, and Russian `_one`/`_few`/`_many`/`_other`.
- Text the UI sends *to the agent* (Ask about this, prefilled drafts) is translated too.
- Don't translate server data, agent output, paths, commands or product names.

## Checks

```sh
npm test                                         # includes both checks below
node packages/web/scripts/check-locales.mjs      # web: same keys, plural forms, placeholders, nothing empty
node --test packages/core/test/i18n-themes.test.ts  # server messages: the same, plus translate()
```

## Adding a language

1. **Code:** add the code to `LANGUAGES` in `packages/core/src/config.ts`, `packages/web/src/lib/i18n.ts` (with its native name and `Intl` tag) and `LOCALE_TAGS`/`LANGUAGE_NAMES` in `packages/core/src/i18n.ts`.
2. **Files:** copy `packages/web/src/locales/en/` to the new code and translate it; do the same for `packages/core/locales/en.json`. The checks list exactly what is missing, including plural forms.
3. **Language names in theme manifests:** add the language to `name`/`description` in `themes/*/theme.json`.
4. **Fonts:** if the script isn't covered by the fonts in `docs/ui-themes.md`, add an OFL fallback font.
