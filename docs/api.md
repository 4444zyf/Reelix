# Reelix HTTP API (for the web UI)

Served by `packages/server/src/http.ts`. All `/api/*` routes except session/login/setup-password need the session cookie (HttpOnly, SameSite=Strict; the browser sends it automatically — use `credentials: "same-origin"`). Requests carrying an `Origin` header from another site are refused. JSON in and out unless noted. Errors: `{ error, code? }` with a 4xx/5xx status.

## Session
- `GET /api/session` → `{ authenticated, needsPassword, language }` (needsPassword = first run: show "set a password"; language = the owner's language `en|zh|fr|ru` or null, public so the sign-in page is translated).
- `GET /api/themes` → installed theme manifests that pass `theme.check` (public). `GET /api/themes/:id/:file` → a file of that theme folder (CSS, fonts, PNG/JPEG/WebP only; public).
- `POST /api/setup-password { password }` (first run only, ≥ 8 chars) → sets the cookie.
- `POST /api/login { password }` → sets the cookie; 401 wrong, 429 rate-limited.
- `POST /api/logout`; `POST /api/password { current, password }`.

## Operations (one registry, three faces)
- `GET /api/ops` → `[{ name, summary, description, effect: "read"|"write"|"destructive"|"admin", input: JSONSchema, tool?, positional?, agentMay?, plugin? }]` (every operation of the running server, plugins' included; the CLI lists and parses from this). `admin` operations answer 403 with code `owner_only` to a caller who may not run them (`docs/plugins.md` §11.2).
- `POST /api/op/:name` body = the operation's input; header `x-request-id` (generate one per click; resending the same id returns the first result) → `{ output, text, actionId?, repeated? }`.

Useful operations and their `output` shapes:
- `title.find { query?, id?, kind?, year? }` → `{ resolved?: Title, how?, candidates: [{ id, kind, tmdb_id, name, original_name, year, overview, poster_path }], note? }`.
- `title.show { id }` → `{ title: Title, have: { folder, episodes, files }, files: [{ id, dest, kind, exists, episodes }], downloads: [...], follows: [...] }`.
- `title.note { id, note }`, `title.set { id, media_class?, folder_name?, douban_id?, bangumi_id? }`.
- `title.find` with a link of a metadata source (`https://movie.douban.com/subject/…`, `https://bgm.tv/subject/…`, `douban:1`, `bangumi:1`) asks the `reelix:metadata.source@1` providers (docs/plugins.md §7.6); TMDB stays the title's identity, and what the source adds (its id, its rating) is merged in. `title.enrich { id, sources? }` → `{ title, ids, results: [{ provider, label, rating?: { value, scale }, note? }] }` asks those sources for a title's ratings and records them.
- `title.trending { kind?, window? }` → `{ items: [{ id, kind, tmdb_id, name, original_name, year, overview, poster_path, rating?, in_library }] }`: TMDB's list, then what the `reelix:trends.source@1` providers add (Bangumi: anime airing now, by how many watch them), found in TMDB, without duplicates.
- `title.play { id, season?, episode? }` → `PlayTarget = { title_id, name, year, kind, poster_path, in_library, season?, episode?, links: PlayLink[], episodes?: [{ season, episode, links }], note? }`; `PlayLink = { app, label, url, autoplay }`, where `app` is the player's provider id (`reelix:player@1`, docs/plugins.md §7.9) and the links follow the owner's list `players`. `library.play_links {}` → `{ targets: Record<title id, PlayTarget>, media_server_error? }`.
- `release.search { title_id?, query?, season?, episode?, sort?, limit?, offset? }` → `{ title, queries, total, offset, releases: Release[], all: Release[], hidden: Release[], search, indexers: [{ indexer, name, ok, count, ms, error?, plugin }] }`; `Release = { handle, title, size, seeders, peers, indexer, publishDate, freeleech, parsed: { resolution, source, codec, hdr[], chineseSubs, group, season, episodes[] }, hasMagnet, hidden?: [{ plugin, reason }], notes?: [{ plugin, note }] }`. `total` and the page `releases` leave out what plugins hid; `all` has the hidden ones last.
- `release.why { handle }` → `{ handle, title, hidden, reasons: Reason[], providers: Reason[], searched_at? }`; `Reason = { kind: "hidden"|"moved"|"note"|"provider", plugin, reason, detail, at }`.
- `subtitle.fetch` and `subtitle.place` → `{ ref?, archive?, files, results: [{ video, placed?, from?, language?, encoding?, warnings, skipped?, why? }] }`; `why` names the plugins whose `subtitle.pick` changed the chosen file's score, with their reasons.
- `release.files { handle }` → `{ name, files: [{ path, size }], magnetOnly }`.
- `download.add { handle, title_id, episodes?, reason?, allow_hidden? }` → `{ hash, name, adopted, started, files, size, warnings[] }`, through the active downloader (`reelix:downloader@1`, docs/plugins.md §7.5). A hidden release is refused with `release_hidden` unless `allow_hidden` is set by the owner (`owner:*`), or by another actor holding the owner's approval of that release. A plugin's `download.before` refusal is `download_refused`; no running active downloader is `no_downloader`; an outcome of the downloader (`needs_auth`, `unavailable`, …) is an error with that code.
- `download.status { hash?, all? }` → `[{ hash, title_id, title_name, name, state, progress, size, reason, note, added_at, filed_at, live?: Transfer }]`, where `Transfer` is the seam's record (`{ id, name, state: queued|checking|downloading|seeding|stopped|error, hasMetadata, done, progress, size, left, folder, contentPath?, marks, addedAt, completedAt?, downSpeed?, upSpeed?, etaSeconds?, peersSending?, ratio?, seedingSeconds?, problem? }`, docs/plugin-reference.md). States: downloading, complete, filed, needs_agent, stalled, gone, removed.
- `download.pause|resume { hash }`, `download.remove { hash, delete_data }` (destructive; has a preview, so a plugin can propose it), `download.file { hash }`.
- `download.downloaders {}` → `{ active, running, providers: [{ id, label, plugin }] }`. The active one is the setting `downloader`, which only the owner changes (Settings → Downloader); Reelix never switches by itself. Its path map is `path_maps.downloaders.<id>`.
- `library.media_servers {}` → `{ active, running, providers: [{ id, label, plugin }] }`: the media server (`reelix:media.server@1`, docs/plugins.md §7.7), chosen by the setting `media_server`, which only the owner changes (Settings → Media server). It is optional. Its path map is `path_maps.media_servers.<id>`.
- `library.list {}` → `{ titles: (Title & { file_count })[], untracked_folders: string[] }`.
- `library.remove { title_id, level: "entry"|"torrent"|"data", season?, episodes? }` (destructive), `library.removed {}`, `library.restore { ids }`.
- `organise { mode: "plan"|"apply", hash?, title_id?, path?, items? }` → `{ plan: { items: [{ source, dest, kind, reason, episodes }] }, problems?, results? }`.
- `activity { limit?, title_id?, status? }` → ledger rows `{ id, op, actor, status, error, title_id, started_at, finished_at, input_json }`.
- `config.show {}` → `{ summary, config, warning? }`; `config.set { path, value }` (`plugins.*`, `proxy.*`, `web.*`, `limits.*`, `downloader`, `media_server` and the address of a service whose secret is stored need the owner: `owner_only` for anyone else without an approval, docs/plugins.md §11.2).
- `secret.list {}` → `[{ key, what, set }]`, including the secrets plugins declare (their `what` from the plugin's strings); `secret.set { key, value }` (only from a password field).
- `plugin.list {}` → `[{ id, version, description, state: "active"|"waiting"|"failed"|"disabled", error?, failures, waitingFor, waitingForPlugins: [{ id, range, version?, state? }], requires: [{ id, range }], owns, provides, hooks, operations, jobs, events, runs, secrets }]`; `plugin.enable { id }`, `plugin.disable { id, with_dependents? }` (owner only) → `{ id, result: "applied"|"failed"|"needs_confirmation", state, dependents?, next }`. `plugin.list` also gives `tools, toolsOn, trial, trialResult?: { calls, hidden, firstChanged, changed, since? }`.
- Plugin pages (docs/plugins.md §12): `plugin.settings { id, lang? }` → `{ id, state, schema?, values, strings, secrets: [{ name, key, set }], buttons, note? }` (never a secret's value); `plugin.configure { id, settings }` (owner only) → the management result plus `errors?: [{ path, message }]`; `plugin.hooks {}` → `[{ hook, mode, plugins: [{ plugin, trial }] }]`; `plugin.hook_order { hook, plugins }`, `plugin.trial { id, on }`, `plugin.tools { id, on }` (owner only) → `{ next }`; `plugin.inspect { id? }` (the agent's `plugin_inspect`); `plugin.press { card, button }` runs a card button's operation as the plugin → `{ operation, text, output, card? }`; `plugin.job_prompt { id, on }` (owner only) → `{ next }`; `plugin.model { id, daily_usd?, roles?, unmetered? }` (owner only) → `{ model, next }`, where `plugin.list` gives each plugin that uses the owner's models `model: { budgetUsd, unmetered, roles, spentUsd, tokens, reached }` (today, since local midnight).
- Translators: `subtitle.translators {}` → `{ active, running, providers: [{ id, label, plugin }] }`; the active one is the owner's setting `translator`.
- Plugin routes (docs/plugins.md §6, §11.5): `/api/plugins/<id>/<path>`, behind the sign-in like every `/api/*` route, one dispatch route for all plugins. A route answers JSON, an attachment or server-sent events, never a page; every answer has `x-content-type-options: nosniff` and `content-security-policy: default-src 'none'; sandbox`. A plugin that is not running answers 404 saying so; a refusal is 400 `{ error, code }`.
- Installing (docs/plugins.md §13), all owner only except `plugin.review`: `plugin.install { source }` (a folder path, `git+<url>#<full commit>` or `npm:<name>@<exact version>`) and `plugin.update { id, to? }` → the approval screen `{ id, what: "install"|"update"|"changed", hash, source: { kind, location, pin? }, declarations, nativeFound, scriptsNotRun, from?, diff?, changelog? }`; `plugin.review { id }` → the same for a plugin waiting for the owner; `plugin.approve { id, hash }` → a management result, `saved-restart-needed` for code; `plugin.uninstall { id, delete_data? }` → a management result plus `deleted`; `plugin.check_updates { id? }` → `[{ id, version, source, available: [{ to, label }], error? }]`. Every approval screen has `requirements: [{ id, range, version?, state?, satisfied }]` (the plugins it requires and what this Reelix has of them), and `declarations` has `requiresPlugins: [{ id, range }]` and `owns`.
- Proposed plugins (docs/plugin-guide.md §8.1): `plugin.propose { folder, note? }` (agent and owner; not a plugin) copies the folder and puts it in the Inbox (item payload `{ pluginProposal }`) → `{ id: "pp_…", plugin, version, by, at, note?, status, folder, files: [{ path, size, change: "added"|"changed"|"removed"|"same" }], diffFrom?, diff }`; `plugin.proposal { id }` → the approval screen with `what: "proposal"` and `proposal` (the same object); `plugin.proposal_decide { id, approve, hash? }` (owner only) → a management result, `saved-restart-needed` when approved. `server.restart {}` (owner only) exists only when Reelix runs under something that starts it again (`REELIX_RESTART=exit`). `plugin.list` also gives `kind: "plugin"|"skills"`, `source?`, `restartNeeded`, `update?: { version }`, `skills`, `setup?`, `jobPrompt?`; states add `installed`, `incompatible`, `changed`.
- Not operations, so not in this API: `reelix plugin new`, `reelix plugin check` and `reelix plugin dev`, the commands for writing plugins ([plugin-guide.md](plugin-guide.md)). They need no running server.
- Proposals (docs/plugins.md §10.3): `proposal.list { status? }`, `proposal.show { id }` → `{ id, plugin, title, why, status, summary, destructive, steps: [{ operation, input, effect, preview: { text, target, counts }, result? }], created_at, expires_at }`; `proposal.decide { id, approve, steps? }` (owner only) runs the ticked steps and returns the same shape with each step's `result: { status: "succeeded"|"failed"|"skipped"|"not_approved"|"declined"|"expired", text? }`. An Inbox item of kind `proposal` carries `payload.proposal`; `inbox.answer` refuses it.
- `doctor { quick? }` → `[{ name, ok: true|false|null, detail, fix? }]`.
- `jackett.indexers { test? }` (from the `jackett` plugin) → `{ servers: [{ server, indexers, health?, error? }], note? }`; `qbittorrent.prefs { keys? }`, `qbittorrent.set_prefs { prefs }` (admin; the agent may), `qbittorrent.torrents { filter?, limit? }` (from the `qbittorrent` plugin), `jellyfin.refresh {}` (from the `jellyfin` plugin: a full library scan), `douban.rating { title_id, douban_id? }` (from the `douban` plugin) → `{ title, douban_id, rating? }`, `inbox.*`, `job.list {}`, `job.run { task }`.
- Chat channels: `channel.list {}` → `[{ id, label, active, linked, may_approve, last_error?, last_error_at? }]`; `channel.allow_approval { id, allowed }` and `channel.unlink { id }` (owner only).
- From the `telegram` plugin: `telegram.status {}` → `{ configured, linked, running, bot?, error? }`; `telegram.link {}` (owner only; the code is not kept in the ledger) → `{ code, expiresAt, bot? }`; `telegram.test {}`.
- From the `push` plugin: `push.devices {}` → `{ public_key, devices: [{ id, label, service, endpoint_id, created_at, last_ok_at?, last_error? }] }`; `push.subscribe { subscription: { endpoint, keys: { p256dh, auth } }, origin, label? }` (only from a signed-in browser whose request has that same, allowed origin); `push.unsubscribe { id?, endpoint? }` (owner); `push.test { endpoint? }` → `{ results }`.
- Subtitles (step 4): `subtitle.search`, `subtitle.fetch { ref, …, verification? }`, `subtitle.list`, `site.status`. They use the `reelix:subtitle.source@1` providers, so they need the running server, as `release.search` does for `reelix:indexer@1`. Follows (step 7): `follow.add|list|remove`. Browser: the routes of the `browser` plugin, `GET /api/plugins/browser/tabs` → `[{ id, owner, url, viewers }]`, `POST /api/plugins/browser/open { url }` → `{ id }`, `GET /api/plugins/browser/<tab>/stream` (server-sent events `frame` with `{ data: <JPEG base64>, url }`), `POST /api/plugins/browser/<tab>/input { type: click|scroll|text|key|goto|back, … }` → `{ ok, url }`.

`Title = { id ("movie:123"|"tv:456"|"local:x"), kind, tmdb_id, media_class ("movie"|"show"|"anime"), name (zh-CN), original_name, folder_name, year, names[], imdb_id, douban_id, bangumi_ids[], runtime_min, seasons: [{ season_number, episode_count, air_date }], poster_path, rating, ratings: Record<provider id, { label, value, scale, at }>, overview, notes, library_folder }`. `ratings` are the metadata sources' (Douban's); `rating` is TMDB's.

## Status and live events
- `GET /api/status` → `{ spend: { usd, tokens, capUsd, capTokens, reached }, inbox (open count), models[], model: { main, background }, configWarning?, jobs: { queued, running, parked }, devPlugin? }`. `devPlugin` is the folder `reelix plugin dev` loaded (docs/plugins.md §13.3); while it is set the web UI shows a banner on every screen.
- `GET /api/events` (SSE, event name `app`): `{ type: "download", hash, state, progress? }`, `{ type: "inbox", id, status }`, `{ type: "action", action }`, `{ type: "job", id, state, kind }`, `{ type: "config" }`, `{ type: "notice", level, text }`, `{ type: "thread", threadId, event: "run_start"|"run_end"|"ask" }`. Use these to invalidate TanStack Query caches.

## Chat threads
- `GET /api/threads` → `[{ id, name, kind ("chat"|"channel"|"job"|"setup"), title_id, job_run_id, updated_at, running, pending_question }]`.
- `POST /api/threads { name? }` → thread. `PATCH /api/threads/:id { name?, archived? }`.
- `GET /api/threads/:id` → `{ thread, messages: UiMessage[], seq, running, pending?: Ask }`. Messages are rebuilt from the saved conversation:
  `UiMessage = { role: "user", text, images? } | { role: "assistant", text (markdown), tools: [{ id, name, label (human line), isError, summary, card? }], error? }`.
- `POST /api/threads/:id/messages { text, images?: [{ data (base64), mimeType }] }` → `{ runId? | queued? | answered? }`. While a run is active the message is delivered after the current tool call.
- `POST /api/threads/:id/answer { questionId, value }` (button or secret field). `POST /api/threads/:id/abort`.
- `GET /api/threads/:id/events?after=<seq>` (SSE, event name `ui`, `id` = seq). Reconnect with the last seq seen; a returning page catches up. Events:
  - `run_start { runId }`, `run_end { runId, state: "done"|"failed"|"interrupted", parkedOn? }`
  - `user_message { text, from?, queued? }`
  - `assistant_start`, `text_delta { delta }`, `thinking`, `assistant_end { stopReason, error? }`
  - `tool_start { id, name, label }`, `tool_end { id, name, isError, summary, card? }`
  - `card { card }` (from the `show` tool)
  - `ask { id, question, kind: "choice"|"confirm"|"text"|"secret", options?, secret_key? }`, `ask_answered { id, text? }`
  - `notice { text }`, `error { message }`
  After `run_end`, refetch `GET /api/threads/:id` to rebuild from the saved conversation.

Cards (`card.kind`): `title { title }`, `candidates { candidates }`, `releases { releases, pick?, reason?, total?, indexers? }` (each row: Download button → `download.add { handle, title_id }` then a short note in the thread), `plan { items, results?, problems?, mode }` (Approve → `organise { mode: "apply", items }`), `progress { hash, name }` (live from download events), `downloads { downloads }`, `image { image (URL), text }`, `verification { image, text }` (code field → send as a message; "open live view" → Browser screen), `subtitles { … }`, `text { text }`.

## Inbox
- `GET /api/inbox?status=open|answered|dismissed|all` → `[{ id, kind ("notice"|"question"|"plan"|"verification"|"summary"), title, body, options[], image_path, payload, source, job_run_id, status, answer, created_at }]`.
- `POST /api/inbox/:id/answer { answer }` (the `inbox.answer` operation refuses the agent and plugins with `owner_only` on an item a job, an approval or an adoption waits on), `POST /api/inbox/:id/dismiss`, `POST /api/inbox/:id/continue` → the job's thread (open it in Chat).
- Image of an item: `GET /api/files?path=<image_path>`.

## Files
- `GET /api/poster?path=/abc.jpg&size=w342` — TMDB posters proxied and cached by the server.
- `GET /api/files?path=…` — images from Reelix's workspace (screenshots, frames, QR codes).
- `POST /api/upload` (multipart `file`) → `{ path, name, size, type }`; then tell the agent about it in a message ("I dropped a subtitle file at <path>").

## Jobs
- `GET /api/jobs` → `{ jobs, runs: [{ id, kind, state, summary, created_at, thread_id }] }`; `POST /api/jobs/:id/run`.
